# OctoAcme Project Management Documentation

Welcome to the OctoAcme project management knowledge hub. This folder contains comprehensive guidance for running projects at OctoAcme, covering everything from initiation through retrospectives.

## Overview of OctoAcme Project Management

OctoAcme's process is designed around a clear, repeatable lifecycle: **initiate, plan, execute, release, and close with a retrospective**. The organization emphasizes customer value, iterative delivery, and defined ownership from the start. Each project begins with a one-pager that captures the problem, goal, stakeholders, success metrics, risks, and resource needs, then moves into planning with backlog prioritization, milestones, dependencies, and a definition of done. This gives teams a consistent foundation for turning ideas into shippable work without losing alignment on outcomes.

The process relies on a small set of core roles with distinct responsibilities. Product leads define the vision, prioritize what matters, and measure success; project managers coordinate timelines, risks, communication, and cross-team work; developers build and test the solution; QA validates acceptance criteria and quality; and stakeholders provide input, approvals, and business context. These personas are intentionally complementary, creating a model where accountability is clear while communication flows across product, engineering, and leadership.

Communication is treated as an operational practice rather than a side activity. OctoAcme uses daily standups, weekly project syncs, milestone demos, and stakeholder updates to keep teams informed and aligned. Risks and blockers are tracked in a risk register, escalated through defined pathways, and communicated through a single source of truth. Quality assurance is embedded throughout the process, not left to the end—with acceptance criteria, definition of done, CI checks, test coverage, security scanning, and smoke tests required before release.

## Key Principles

OctoAcme projects are built on these core principles:

- **Customer-first**: Prioritize customer value and usability.
- **Iterative delivery**: Deliver small, testable increments.
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead.
- **Data-informed decisions**: Measure impact and iterate based on evidence.
- **Psychological safety**: Encourage feedback and learning.
